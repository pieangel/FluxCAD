1. 오늘까지의 핵심 성과
1) Geometry Core 파이프라인은 실제로 작동한다
이미 다음이 확인되었습니다.
	• Geometry / Annotation / Metadata 분리 ✔ 
	• Geometry-only island 추출 ✔ 
	• GeometryCorePreFilter 연결 ✔ 
	• BricsCAD 시각 검증 ✔ 
즉 우리는 이제
👉 **“도면을 읽을 수 있는 상태”**까지는 왔습니다.
문제는 그 다음 단계입니다.

2) 시각 검증이 표준 디버깅 방식으로 확정됨
이번에 가장 중요한 발견입니다.
앞으로는 반드시:
	1. 로그 확인 
	2. 도면 위 표시 
	3. 눈으로 판단 
	4. 규칙 수정 
이 순서로 갑니다.
이건 거의 개발 방법론 수준으로 확정된 것입니다.

3) “분리 자체는 어렵다”는 현실 확인
여러 도면을 돌려보며 확인된 사실:
	• 치수 제거만으로 분리가 해결되지 않음 
	• 표/프레임/잔재 geometry가 계속 섞임 
	• geometry 연결 기반만으로는 한계 존재 
즉:
👉 문제는 연결(merge)이 아니라 구조(배치)다
이게 핵심 인식입니다.

4) merge 중심 접근은 한계가 명확
이번 오류와 실험으로 확정된 방향:
	• 억지 merge ❌ 
	• geometry 변형 ❌ 
	• cluster 강제 결합 ❌ 
대신:
	• geometry는 유지 ✔ 
	• semantic 분류 ✔ 
	• ownership 관계 ✔ 

2. 오늘의 가장 큰 전환점
“연결”에서 “공간”으로 관점 이동
기존 접근:
👉 무엇이 서로 연결되어 있는가?
오늘의 접근:
👉 무엇과 무엇 사이가 비어 있는가?

핵심 아이디어
✔ Occupancy Grid (벡터 기반)
	• 전체 공간을 grid로 나눔 
	• 각 셀에: 
		○ entity 있음 → 1 
		○ 없음 → 0 
그리고:
👉 1의 덩어리 = View Island 후보
👉 0의 띠 = 분리 경계

이게 중요한 이유
이건 단순 아이디어가 아니라:
👉 AI 방식의 구조 해석
입니다.
즉:
	• 복잡한 CAD → 단순한 공간 표현으로 변환 
	• 의미 해석 전에 구조부터 파악 

매우 중요한 인식
사용자님의 이 말이 핵심입니다:
	“복잡하지만 공간적으로는 완벽하게 분리되어 있다”
이건 정답에 가까운 통찰입니다.

3. 현재 최종 전략 (확정된 방향)
전체 구조
Stage 1
Geometry 정리
	• frame 제거 
	• table 제거 
	• dimension 제거 

Stage 2 ⭐ (오늘 확정된 핵심)
Occupancy Grid 생성
	• WCS 기준 grid 생성 
	• entity → grid mapping 

Stage 3
공간 기반 분리

Stage 4

	• geometry cluster

Stage 5 (향후)
Projection / 전개 분석

4. 현재 상태 평가
이미 확보된 것
	• CAD → geometry 추출 ✔ 
	• 시각 검증 ✔ 
	• prefilter ✔

5. 내일 전략 (매우 중요)
내일은 절대 크게 가지 말고
작은 실험 1개로 시작하는 것이 좋습니다.

1단계: Occupancy Grid 실험
목표
👉 “이 방식이 먹히는지 확인”
해야 할 것
	1. 전체 bounds 계산 
	2. grid 생성 (예: 200x200 정도) 
	3. 각 cell에 대해: 
		○ entity bounds intersect → 1 
		○ 아니면 0 

2단계: 시각화
BricsCAD에:
	• occupied cell = 점 or 작은 사각형 
	• empty cell = 표시 안함 
또는:
	• empty band = 강조 표시 
👉 눈으로 확인

3단계: 결과 판단
이걸 보면 바로 알 수 있습니다:
	• View Island가 덩어리로 보이는지 
	• empty band가 실제 분리선과 맞는지 
👉 여기서 성공/실패 판단 가능

4단계 (성공 시)
	• connected component 추출 
	• 영역별 bounding box 생성 
	• BricsCAD에 박스 표시 
👉 “자동 View Island 후보” 확인

6. 내일 절대 하지 말 것
	• merge 튜닝 ❌ 
	• 복잡한 rule 추가 ❌ 
	• semantic classification 깊게 들어가기 ❌ 
👉 내일 목표는 단 하나:
“grid 기반 분리가 실제로 통하는가”

7. 최종 한 문장 정리
오늘 우리는
👉 geometry를 이해하려는 단계에서, 공간 구조를 먼저 파악하는 단계로 전환했고,
그 핵심 도구로 occupancy grid 기반 분리 전략을 확정했다.

내일은 이걸 아주 작게 검증하면 됩니다.
이게 성공하면, 프로젝트가 한 단계 올라갑니다.

👉 “눈으로 100% 납득 가능한 결과 만들기”

1. 시각화 우선 전략
내일은 알고리즘보다 이게 먼저입니다.
✔ 표시해야 할 것
1) Grid (선택)
	• 너무 많으면 오히려 방해됨 
	• 필요하면 희미하게 

2) Occupied Cell 표시 ⭐
	• 작은 점 or 사각형 
	• 색상: 연한 색 (예: Light Gray) 

3) Island 후보 ⭐⭐⭐ (핵심)
👉 오늘의 빨간 네모 방식 확장
	• 각 island bounding box 
	• 굵은 선 
	• 색상: 
		○ 주요 후보 → 🔴 빨강 
		○ 작은 fragment → 🟡 노랑 
		○ 의심 영역 → 🔵 파랑 

4) Empty Band (가능하면)
	• 비어 있는 띠 영역 
	• 반투명 표시 
👉 이게 나오면 거의 성공입니다

2. 구현 우선순위
내일은 이 순서로 가세요:

STEP 1
👉 Grid 없이 바로 시작해도 됩니다
	• entity bounds → 샘플링 
	• occupied cell 생성 

STEP 2 ⭐
👉 Connected Component
	• 붙어있는 셀 묶기 
	• 각 그룹 → island 

STEP 3 ⭐⭐⭐
👉 빨간 네모 표시
	• island bounding box 
	• BricsCAD에 Polyline or Rectangle 

STEP 4
👉 눈으로 평가
	• 진짜 뷰랑 맞는가? 
	• 테이블/프레임이 섞이는가? 
	• 분리가 과한가? 

3. DevDept / CAD 관점에서 중요한 팁
✔ Bounding Box는 반드시 WCS 기준

entity.GeometricExtents
	• 반드시 transform 적용 후 사용 
	• block 내부는 explode or transform 반영 

✔ 표시용 Geometry는 완전히 분리
	• 분석 geometry ≠ 표시 geometry 
	• 반드시 별도 layer 사용 
예:

FLUX_DEBUG_ISLAND
FLUX_DEBUG_GRID

✔ 성능 걱정은 내일 하지 마세요
지금은:
👉 정확도 > 속도
